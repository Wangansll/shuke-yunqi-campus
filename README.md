南宁数字科技学院（吉利创办，广西南宁）校园服务小程序。课程：《移动互联网应用开发》项目制课程作品。
AppID `wx5cbc370db8d288e9` · 云开发环境 `prod-d2gc3nmna23946d86`

**一句话**：能问（AI 助手 + 校内知识库）、能查（校园导览）、能办事（报修 / 互助）、能跨境（东盟汇率与翻译）。

### 登录走云托管

云托管会把调用者 openid 注入 `X-WX-OPENID` 请求头。`cloudrun/wxlogin/` 就是部署上去的服务
（登录 + 工单 + 互助 + 健康检查）。实测在模拟器里点「微信授权登录」：

```
openid = oUncpxiZOJwQej8Ns8wQ2yTfBOwE   （真实 openid，非模拟）
```

环境自检 7 项里 6 项通过，唯一失败的是「自建云函数」——上面说的平台限制，自检会直接写明原因。

### 云端不可用时的兜底

接口不通（没配数据库 / 网络异常）时，报修与互助会落本机 storage，列表明确标注
「本机暂存 · 未同步云端」，自检里也会写出原因，不假装成功、不编造数据。

### 美食鉴赏：记录有什么菜、卖得怎样、同学怎么说；下单走页头「开饭」

150 家店（校内 67 个档口 + 校门口 83 家）、2072 道菜、1144 条评价，来自外卖菜单快照（2026-11-18）。
**不含价格、没有购物车、不代下单**——避免看起来能点餐的假功能。唯一的出口是页头右上「开饭」（小字：跳转美团）：跳美团外卖小程序，拉不起就复制链接，价格与配送费以美团内为准。按钮外面套了一层 2.4 秒周期的呼吸光晕与扩散光环，深棕刊头上不至于被当成一张静态贴纸。

- 图鉴：范围（全部 / 校内 / 校门口）× 品类（招牌主食 / 主食 / 配菜加料 / 饮品 / 小食 / 烤串 / 套餐）× 搜索（菜名或店名）三层同时生效，有图的排前面
- 销量榜：同名菜只留卖得最好的一家，取前 60；菜品月售高于整店月售的按快照误差处理，不显示也不上榜
- 口碑：全校 1144 条评价（好评 694 / 中评 211 / 差评 118），按店展开看全部，每条带平台判定与「推荐菜」；每个店的评价条数、三段分布条都在列表上直接可见

**图片**：`pkgFood/images/dish/` 下 107 张，取自「菜品素材库」，按归一菜名命名，压到长边 240px（合计 1.1MB）。320 道菜的图是 AI 生成的，详情页标「AI 图」，页脚也有说明。没图的菜用「首字 + 品类底色」占位，不拿同一张图糊一屏。

**分包**：美食页在 `pkgFood` 分包里（数据 220KB + 图 1.1MB），主包不放菜品明细；主包只留 `data/foodstat.js` 里的几个统计数字给首页卡片用。

店铺归属按菜品行自带的「校内/食堂」两列判定，不按店铺表默认值（`炸鸡套餐~` 等 4 个名字其实是菜名、店铺表里查不到，之前被误算进校内，共 353 道菜，现已归到校门口）。

清洗规则：价格式菜名（`¥4.8￥5.1`）、纯数字、`#★` 开头、`发布者声明` 一律丢弃；OCR 把 `+` 认成 `十` 的还原（饭十青菜 → 饭+青菜）；括号没配对的砍掉残尾；同店同名归一后只留月售最高、有图优先的一条。评价里被截断的半句、平台提示、`多用户，美` 这类残句也一并滤掉。

### 为什么砍掉宿舍报修

同一个理由：工单只写进我们自己的 MySQL，**没有后勤/宿管会看到**，也没有学校系统对接，
用户填完没人处理，属于"假闭环"。已下线（页面在 `docs/attic/report/`），
入口改成**办事指南**——15 件事全部来自学校下发文件或官方 App 入口，只讲"要带什么材料、去哪办、按哪份文件办"。

### 课表：查过了，没有

全站语料 2775 篇里搜「课表/课程表/上课时间表」只命中 6 篇，全是「教室课表牌采购项目」这类；
「教学计划/培养方案」65 篇都是修订工作会的新闻；12 个专业介绍页只有培养目标、学制、学位，
**没有课程表**。真实课表在教务系统里按班级/学号生成，需登录，外部拿不到。

### 为什么外部平台只能「跳」不能「嵌」

小程序 `web-view` 只能加载**自己名下、已 ICP 备案并放了微信校验文件**的域名，
所以嵌不了 tmall.com / meituan.com；淘宝也没有微信小程序。实测（Edge 无头渲染）：
这两个站点在普通网页的 iframe 里能渲染，但登录态、支付、深链在嵌入态都不可用，
所以正确做法是「站内自建 + 需要时跳转」，而不是硬嵌。
截图留在 `docs/shots/iframe-feasibility.png`。

- 知识库条目里不出现任何学号、姓名、手机号；只保留制度与流程

**抽不出文字的**：18 个 PDF 是扫描件（没有文字层），需要 OCR 才能入库，目前留空不硬编。

### 外卖橱窗：为什么是「演示」，不是抓取

美团没有公开接口：H5 首页只返回 54 KB 的 JS 空壳（`菜品/商家/评论` 关键词出现 0 次），
数据要登录 + 定位 + 设备指纹才会加载，直接抓取违反其协议，改版就失效。

所以做成**演示橱窗**（`pages/waimao`）：

- 店名、菜名、月售、口碑短句**按用户提供的截图人工转录**，页面顶部标日期
- **不含价格**：每行右侧写「不标价」；没有购物车、没有下单
- 图片用「色块 + emoji」占位，不搬美团菜品照片（版权 + 不伪造）
- 底部只有「去美团看真实菜单」（复制链接 + 说明为什么打不开 App）

### 快递查询：为什么换成了正式接口

一开始走快递100 的**免费网页通道**（`/query?type=&postid=`，服务端带 Referer），11-17 还能用（拿到 28 条轨迹），到 11-18 就对所有单号返回「查无结果」——连真实在途的圆通单号也查不到，属于上游收紧。

改成正式接口：`POST poll.kuaidi100.com/poll/query.do`，`sign = MD5(param + key + customer).toUpperCase()`。

- 凭据放 `cloudrun/wxlogin/kdconfig.js`（也可以环境变量 `KUAIDI100_CUSTOMER` / `KUAIDI100_KEY` 覆盖）
- **注意顺序**：32 位那串是 `customer`，另一串是 `key`，反过来会报「授权信息错误」
- 没配凭据时自动退回免费通道，并在页面上如实提示「公开通道受限」，不假装能查

隐私面单：页面可选填**收件人手机后四位**，随 `param.phone` 一起提交，不落本地存储。

### 意见反馈与荣誉：统一进管理员后台

小程序「我的 → 意见反馈」分**纠错 / 建议 / 资料补充**三类提交，先落本机、能连云端时同步到 `board_posts`（`cat=feedback`）。课表建好后可选择提交分享，作为一条「资料补充」汇入同一处，并获得「资料补充者」头衔。

- **荣誉**：先驱者（12-20 前登入金色、之后铜色）、资料补充者 / 纠错贡献者 / 意见反馈者（铜）、校园共建者（前三项满足两项及以上，银色统称）；头衔取已获最高级，显示在头像下方，互助墙发帖也带。
- **管理员后台**：`docs/admin-feedback/index.html`（单文件，双击浏览器打开）。传本机数据有两种方式：①在小程序「我的 → 意见反馈 → 复制全部反馈给管理员」粘贴；②填云托管公开地址走接口拉取（需接口允许跨域）。可按三类统计、筛选、标记已处理，状态存本机浏览器，不上传服务器。
- **边界**：线上 `/api/posts` 不回传班级、头衔等字段，且改后端需要管理员密钥；当前身份靠发帖机本机映射补回，换设备只见正文。
